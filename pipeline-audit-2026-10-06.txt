2. AUDIO INGEST
==========================================================================================

  Capture tool        parec (PulseAudio/PipeWire), started as a child of feed-mic.py
  Device choice       name/description substring argument; otherwise the first non-PCI
                      source; the operator can switch from /status/<token> (set_device)
  Format on capture   16 kHz, s16le, 2 channels. PulseAudio does the resampling (the
                      mixer's native rate is converted by parec, not by our code)
  Channel decision    the first ~1 s of audio (RATE samples) decides L, R or mix; one side
                      must be 3x louder to win, otherwise L+R are averaged. Re-checked on
                      every open()
  Chunk size          CHUNK_MS = 100 -> 1600 mono samples = 3200 bytes per WebSocket frame
  Gain                software multiply with clipping (default 1.0)
  DSP                 none (no AGC, no noise suppression, no high-pass filter)
  Server side         AudioBuffer: one growing bytearray, int16. No resampling on the
                      server. buf.sample_rate is TAKEN FROM THE CLIENT's config message
                      (server.py:159); see the gaps section
  Windowing           RMS over 0.1 s windows (SPEECH_WINDOW_S) for has_speech() and
                      trailing_silence_seconds(); has_trailing_silence() takes ONE RMS over
                      the last 0.6 s
  To Whisper          int16 -> float32 / 32768 (stt.py:121). The whole chunk goes in one call

3. SPEECH DETECTION / GATING (what is active right now)
==========================================================================================

  ACTIVE:   RMS loudness gate inside AudioBuffer (audio_buffer.py:31-99)
  INACTIVE: Silero VAD (faster-whisper vad_filter) - WHISPER_VAD_FILTER = False
            (config.py:76, used at stt.py:126). Off since 2026-09-20: it deleted
            speech the loudness gate had already passed ("be my" instead of
            "the cross be my glory ever to").
  No webrtcvad, no Silero outside Whisper, no spectral or ML gate anywhere.

  When a chunk is cut (cut_reason, audio_buffer.py:75), checked in this order:
    1. duration < MIN_SPEECH_S (0.5 s)            -> no cut
    2. no 0.1 s window >= SILENCE_THRESHOLD (120) -> no cut (and the buffer is NOT cleared)
    3. duration >= MAX_BUFFER_S (8.0 s)           -> cut "max_buffer"
    4. duration >= MIN_TRIGGER_S (1.5 s) AND the last 0.6 s RMS < 120 -> cut "silence"

  Measured 2026-09-20 (transcripts/2026-09-20.jsonl): 571 silence cuts and 33 max_buffer
  cuts over the service (~49 min).

  Filters after Whisper: see section 4. Debris check (no \w character) at pipeline.py:137.

5. TRANSLATION
==========================================================================================

  Yes, MT is live.
  Primary   ai4bharat/indictrans2-en-indic-dist-200M via transformers
            (trust_remote_code), fp16 on cuda                          translator.py:221
  Fallback  facebook/nllb-200-distilled-600M, used only if IndicTrans2 fails to load
                                                                       translator.py:413
            !! BROKEN, see the gaps section: NLLB has no translate_sentences_sync
  Targets   ml (mal_Mlym), te (tel_Telu), hi (hin_Deva). Source en (eng_Latn)
  Unit      a SENTENCE. Fragments are never translated: ml/te/hi are verb-final
  Sentence assembly:
     - English split on (?<=[.!?])\s+ ; parts with no word character are dropped
     - the last part is held; a held full stop is accepted or rejected by the
       capitalisation of the next chunk's first letter (Stage 2b)
     - hold limits: SENTENCE_GRACE_S 3.0 s (held text ends in a full stop),
       MAX_SENTENCE_HOLD_S 16.0 s (it doesn't), both measured as silence;
       MAX_PENDING_CHARS 400 flushes regardless
     - trailing ellipses and dangling , ; : - are stripped before MT only
     - partial words with a trailing hyphen at chunk edges are dropped on join
  Chunking for MT:
     - sentences over 200 chars (CLAUSE_SPLIT_CHARS) are split at "lowercase/comma +
       Capital" boundaries, packed back up to 200, then rejoined per sentence
  Batching   ONE generate per chunk: (sentences x 3 languages) rows, max_length 256 in/out,
             num_beams=5, no_repeat_ngram_size=4, repetition_penalty=1.15
  Context    MT_USE_CONTEXT = False. The previous sentence is passed in but IGNORED.
             If enabled: a 1-sentence prefix, plus a recovery that retries with no
             context when the output comes back short
  Pre/post   SOURCE_REWRITES (contrast->compare, idol->false god, "not dishonesty")
             GLOSSARY (steward/master pinned in ml/te/hi; populated, not empty)
             Malayalam legacy-codepoint normalisation
  Concurrency  its own asyncio.Lock, separate from Whisper's. STT and MT share the GPU
  Measured MT latency, 2026-09-20: median 0.99 s, p90 2.59 s

8. KNOWN GAPS (from the code)
==========================================================================================

  Correctness / reliability
  [G1] THE NLLB FALLBACK CRASHES ON THE MAIN PATH. NLLBTranslator defines only
       translate_all_sync. _AsyncTranslatorBase.translate_sentences calls
       self.translate_sentences_sync (translator.py:218), which doesn't exist on NLLB,
       so every _flush_many raises AttributeError. server.py:202 catches it and the
       utterance is DROPPED. If IndicTrans2 ever fails to load, the English still shows
       but nearly all translations are lost.

  [G2] A silent buffer is never cleared. When no window reaches SILENCE_THRESHOLD,
       cut_reason() returns None and the bytes keep piling up (audio_buffer.py:89;
       config.py:245-247 admits this). Effects:
         - after a long quiet stretch (worship music below 120, a prayer, an
           announcement break) the first loud window triggers an immediate
           "max_buffer" cut holding MINUTES of audio. Whisper decodes it in 30 s
           windows, which means a latency spike and "you" artifacts on the silent parts
         - _window_rms() reruns over the WHOLE buffer every 100 ms, so CPU cost grows
           with the length of the silence (quadratic over the stretch)
       Fix shape: trim leading silence, or cap the buffer at MAX_BUFFER_S of silence.

  [G3] The server trusts the client's sample rate. buf.sample_rate = msg["sampleRate"]
       (server.py:159) changes the buffer's timing maths, but nothing resamples, and
       Whisper always assumes 16 kHz. /ws/mic has no token (hub.py:23), so anything
       on the church WiFi can open it and inject audio or a bad rate.

  [G4] Cuts are blocked while a chunk is processed. ws_mic awaits process() (STT, then
       MT for any finished sentences) inside the receive loop (server.py:201), so no
       new audio is read or cut until both finish. Audio queues in the socket rather
       than being lost, but every MT batch adds to the delay of the NEXT chunk.

  [G5] There is no end-to-end latency figure: no timestamp for when speech ended or
       when the screen received it.

  Noise robustness
  [G6] The only speech detector is a fixed RMS threshold, tuned to one room and one
       board gain. A fan, HVAC, crowd noise or music above 120 is "speech", so cuts
       stop being triggered by silence and fall back to 8 s max_buffer cuts, which land
       mid-word. A trained VAD (Silero standalone, used only for cut decisions, not
       inside Whisper) would separate noise from speech without the deletion problem.
  [G7] The threshold doesn't adapt (no noise-floor tracking), and the silence test uses
       one RMS over 0.6 s, so a single cough or clap resets it.

  Long-form / sermon handling
  [G8] Whisper keeps no context between chunks (condition_on_previous_text=False and the
       prompt is static), so names and terms can change from chunk to chunk.
  [G9] No terminology memory in MT beyond the static GLOSSARY (MT_USE_CONTEXT off), so
       a character's name can still change between sentences in one sermon.
  [G10] The unpunctuated run-on backstop is 400 chars, then the 200-char clause split.
       A preacher who rarely pauses still produces 8 s chunks cut mid-word.
  [G11] There is no scripture-verse detection or lookup. The config names reference
       Bibles (KJV / BSI OV) "for (later) verse lookup", but none exists, so quoted
       verses are machine-translated rather than shown from the agreed Bible.

  Language coverage
  [G12] Source is English only (the model is English-only, language is fixed). Speech
       in Malayalam, Telugu, Hindi or Tamil, or switching mid-sentence, is forced into
       English or dropped. Many Indian congregations switch languages mid-sermon.
  [G13] Targets are fixed at ml/te/hi in config. Adding Tamil/Kannada needs a config
       change and a restart; IndicTrans2 supports them.

  Accessibility / output
  [G14] No TTS / audio channel for listeners who can't read the screen or are visually
       impaired.
  [G15] Recap is extractive only; no abstractive summary (known, see the memory note
       next-version-summarisation).

  Operations
  [G16] One microphone, one buffer, app-wide state (server.py:111-129). A second
       feed-mic.py silently replaces the first.
  [G17] Recording the audio (AUDIO_TEE) is opt-in, so a bad service usually has no audio
       to replay unless someone turned it on beforehand.
